# かけらの泉

投げるだけのメモ。つなぐのは機械。

- 意味の近さは **端末の中で動く無料モデル**（paraphrase-multilingual-MiniLM-L12-v2）で計算。外部の有料APIは使わない。
  初回だけモデル（約120MB）を Hugging Face から読み込み、以後はブラウザに保存されたものを使う。
- 保存先は Supabase（Free）。**ログインした本人の行しか読めない・書けない**（RLS）。新規登録は止める。
- 試すだけなら `?demo` を付けて開くと、ブラウザの中だけで動く（閉じると消える）。

## 1. Supabase の準備（ダッシュボードで。キーはどこにも貼らない）

1. **SQL Editor** → New query → `supabase/01_schema.sql` の中身を丸ごと貼って **Run**。
2. **Authentication → Users → Add user → Create new user**
   自分のメールアドレスと、**ログインに使うパスワード**（パスワード管理に保存しておく）を入れ、**Auto Confirm User** にチェック。
3. **Authentication → Sign In / Providers**（Settings）で **Allow new users to sign up をオフ**。
   これで自分以外はアカウントを作れない。

アプリにはメールアドレスとパスワードで入る（無料プランではログイン用メールの文面を変えられないため、メールのコード方式はやめた）。

## 2. config.js に鍵を入れる（自分のエディタで）

**Project Settings → API Keys**（または Data API）から次の2つを `config.js` に貼る。

- `supabaseUrl`：Project URL（`https://xxxx.supabase.co`）
- `supabaseKey`：**Publishable key**（`sb_publishable_…`）または旧 **anon public** キー

この2つは公開される前提の鍵で、RLS があるので他人には何も見えない。
**`service_role` / `secret` キーは絶対に入れない。**

## 3. 手元で試す

```bash
cd ~/Desktop/アプリ/KAKERA && python3 -m http.server 8765
```

ブラウザで http://localhost:8765 を開き、メールアドレスとパスワードで入る。

## 4. 公開（GitHub Pages・無料）

GitHub に **public** リポジトリ（例：`kakera-izumi`）を作ってこのフォルダを push し、
Settings → Pages → Branch: `main` / `(root)` で公開。PCでもスマホでも同じURLで開ける。
（無料の GitHub Pages は public リポジトリのみ。中に入っている鍵は上の公開用だけなので問題ない）

## 5. Gmail の見張り番（メルマガの自動取り込み）

### A. 取り込み専用の鍵を作る（Supabase）

1. **SQL Editor** で `supabase/02_ingest.sql` を丸ごと貼って **Run**
2. New query で次を実行（メールアドレスは泉にログインするときのもの）

   ```sql
   select kakera_private.issue_ingest_token('ログインに使うメールアドレス');
   ```

3. 下に出た長い英数字が **取り込み専用の鍵**。一度しか表示されないので、すぐ B-3 で使う
   （この鍵でできるのは泉にかけらを足すことだけ。読む・消すはできない）

### B. Apps Script を置く（メルマガ用の Gmail アカウントで）

1. メルマガが届く Google アカウントでログインして https://script.google.com → **新しいプロジェクト**
2. 中身を全部消して `gas/gmail-watcher.gs` を丸ごと貼り、💾 保存。名前は「泉の見張り番」など
3. 左の ⚙ **プロジェクトの設定** → 下の **スクリプト プロパティを追加** で5つ入れる

   | プロパティ | 値 |
   |---|---|
   | `SUPABASE_URL` | config.js と同じ Project URL |
   | `SUPABASE_KEY` | config.js と同じ Publishable key |
   | `INGEST_TOKEN` | A-3 の鍵 |
   | `SENDERS` | 取り込むメルマガの差出人。カンマ区切り。`@example.com` と書けばそのドメイン全部 |
   | `YAHOO_ADDRESS` | 自分の Yahoo メールのアドレス（ここからの転送だけ受け付ける） |

4. 左の `<>` エディタに戻り、上の関数選びで **tryIt** → ▶ 実行
   - 初回は権限の確認が出る。「このアプリは Google で確認されていません」と出たら
     **詳細 → 泉の見張り番（安全ではないページ）に移動 → 許可**（自分で書いたスクリプトなので大丈夫）
   - 下の実行ログに「沈む予定のメール」と各段落の頭が出る。まだ何も送っていない
5. 中身がよさそうなら、関数選びで **setup** → ▶ 実行。これで1時間ごとに動き出す

取り込んだメールのスレッドには `kakera-done` ラベルが付く（受け付けなかったメールにも「見た」印として付く）。
差出人を足したいときは `SENDERS` を書き換えるだけ。過去14日分までさかのぼって見る。
取り込んだかけらは、アプリを開いたときに端末で意味を計算する（それまで波紋・検索には出ない）。

## 6. Yahoo メールの「泉行き」フォルダを一括取り込み

1. Yahoo メールの **設定 → IMAP/POP/SMTPアクセスとメール転送** で
   **「Yahoo! JAPAN公式サービス以外からのアクセスも有効にする」** をオンにして保存
   （Yahoo! JAPAN ID を「パスワードを使わないログイン」にしていると IMAP は使えない。その場合はパスワードを設定する）
2. 取り込み専用の鍵を用意する。Apps Script の `INGEST_TOKEN` と同じものでよい
   （見られないときは SQL Editor で `select kakera_private.issue_ingest_token('ログインに使うメールアドレス', 'yahoo');` を実行して新しく作る）
3. ターミナルで、まず「見るだけ」

   ```bash
   cd ~/Desktop/アプリ/KAKERA && python3 tools/yahoo_import.py
   ```

   Yahoo のアドレスとパスワードを聞かれる（パスワードは画面に出ない・保存しない）。
   最初の5通ぶんの「何が沈むか」が表示される。
4. よければ本番

   ```bash
   cd ~/Desktop/アプリ/KAKERA && python3 tools/yahoo_import.py --send
   ```

   アドレス・パスワード・取り込み専用の鍵を聞かれる。同じメールは二度入らないので、何度実行しても大丈夫。
   フォルダ名が違うときは `--folder 別の名前` を付ける。

## 調整つまみ

`app.js` の先頭：

| 名前 | 意味 | 初期値 |
|---|---|---|
| `RIPPLE_MIN` | 波紋に出す近さ | 0.40 |
| `THREAD_MIN` | 糸の先に出す近さ | 0.36 |
| `SEARCH_MIN` | 探すときに出す近さ | 0.30 |

関係ない文どうしは 0.1〜0.3、近い話は 0.4 以上になりやすい。

## 中身

| ファイル | 役割 |
|---|---|
| `index.html` / `style.css` | 画面 |
| `app.js` | 投げる・波紋・探す・糸の先・地層・Claudeに聞く |
| `store.js` | Supabase とのやりとり（`?demo` のときはメモリ） |
| `embed-worker.js` | 端末内の埋め込みモデル |
| `supabase/01_schema.sql` | テーブル・RLS・検索関数 |
| `supabase/02_ingest.sql` | 取り込み専用の鍵と取り込み口 |
| `gas/gmail-watcher.gs` | Gmail の見張り番（Apps Script） |
| `tools/yahoo_import.py` | Yahoo メールのフォルダを一括取り込み |

取り込み（Gmail・Yahoo・Notion）で入ったかけらは `embedding` が空のまま入れてよい。
アプリを開いたときに、端末のモデルで順に埋め込んでいく（`backfill`）。

## これから足す順番

1. ✅ 投げる・探す・波紋
2. ✅ スマホのホーム画面に追加
3. ✅ Gmail の見張り番（Apps Script）：メルマガ用の Gmail に届くメルマガを1時間ごとに取り込む。
   登録した差出人と、自分の Yahoo からの転送だけ受け付ける。転送の前置きは取り除く。
4. Yahoo メールの「泉行き」フォルダを IMAP で一括取り込み
5. Notion の書き出しを一括取り込み
6. **レンズ**：英単語／英語の記事／会計／日々 を自動で見分けて絞り込む（タグ付けはしない）
7. **今日の英単語**：1日1語が湧く。「知ってる」で卒業（検索には残る）、「まだ」は間隔を広げて再出現。
   メルマガの中でその単語が出てくる文も一緒に出す。

### 6. レンズの作り方（予定）

- 埋め込みを作るときに、ついでに `lens` 列へ1つ書き込む。手で付けることはない。
- 見分け方：
  - **英単語**：短い（80字くらいまで）かけらで、中心が英単語か英語の言い回し（例：`"skepticism" の発音…`）
  - **英語の記事**：本文の半分以上が英語で、ある程度長い
  - **会計 / 日々**：それ以外を、それぞれの「お手本の文」の埋め込みとの近さで振り分ける
- 振り分けのルールを直したら、アプリを開いたときに全部を見分け直す（端末の中で済む）。
- 画面は「泉を探す」と地層の上にレンズのボタンを並べ、押すとそのレンズだけに絞る。

### 7. 今日の英単語の作り方（予定）

- 対象は、英単語レンズのかけらから取り出した単語と、**メルマガ（英語の記事）から自動で拾った単語**。
  メルマガからは、よく出てくるのに自分のかけらにまだ無い単語を選ぶ（ごく基本的な単語は除く）。
- 新しく `words` 表を作る：単語・元のかけら・状態（学習中／卒業）・次に出す日・間隔。
- 「まだ」を押すと、次に出す日を 1 → 3 → 7 → 14 → 30 日後と延ばしていく。「知ってる」で卒業する。
  卒業してもかけらは消えないので、検索には残る。
- 例文：メルマガから来たかけら（`source = 'gmail' / 'yahoo'`）の中で、その単語が単語として出てくる文を切り出して出す。
  なので、3（Gmail の見張り番）が入ってから本領を発揮する。

## メモ

  （Gmail の見張り番を入れれば1時間ごとに触るので止まらなくなる）
